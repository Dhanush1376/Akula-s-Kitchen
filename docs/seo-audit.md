# Akula's Kitchen — SEO Audit

Audit date: 2026-10-31. Method: read the repository (frontend Vite/React SPA, Express/Mongoose backend, Vercel/nginx config) **and** checked the live site with `curl` (normal and Googlebot user agents), so the findings describe actual behaviour, not just which files exist.

## 2. Verified problems (live behaviour)

### Critical

1. **Canonical host conflict.** `https://akulas.kitchen/` answers `308 → https://www.akulas.kitchen/`, but every canonical, `og:url`, sitemap `<loc>` and robots `Sitemap:` line uses the apex host. Google is told the preferred URL is one that redirects. This is a Vercel domain setting, not code. Code must use one configurable site URL, and the domain redirect must point the same way.
2. **Every URL returns identical HTML.** `/collections` and every product URL return the homepage `<title>Akula's Kitchen | Authentic Flavors & Premium Culinary Experiences</title>`, the generic description, `canonical=https://akulas.kitchen/` and `og:image=/og-image.png`. Non-rendering crawlers see this, including WhatsApp, Facebook, X, LinkedIn and Bing's first pass. So:
   - every shared product link previews as the homepage;
   - the static `<link rel="canonical" href="https://akulas.kitchen/">` on every page tells crawlers that read raw HTML that every page is a duplicate of the homepage.
3. **The sitemap is a stale static file.** Vercel serves files in `public/` before it applies rewrites, so the committed `frontend/public/sitemap.xml` always wins over the dynamic rewrite. That file is only regenerated when the backend runs locally inside the monorepo (it writes to `../frontend/public`), which is why `git status` shows it modified. In production (Render) the write silently fails. A product created through the admin panel never reaches the served sitemap until someone commits the file again.
4. **The sitemap lists non-canonical product URLs.** It uses `/product/<ObjectId>` (all 18 products), while products already have clean unique slugs (`/product/mango-avakaaya`) and the API accepts both. The same product is reachable at two URLs, and all internal links (`getProductRoute(productId)`) use the ObjectId form.
5. **The `api/sitemap.js` function is broken.** It imports `../src/utils/logger.js`, which does not exist (the logger lives at `src/utils/core/logger.js`). It never ran in practice because of item 3.

### High

6. **Duplicate and conflicting metadata in the rendered DOM.** The static meta in `index.html` (description, og:_, twitter:_, canonical) is never removed. Helmet then adds its own tags next to them, so rendered pages carry two descriptions, two canonicals, and so on. `MainLayout` _and_ each page render `<SEO>`, so Organization + WebSite JSON-LD appear twice on every page.
7. **Product structured data is inaccurate.**
   - Product pages emit their own Product JSON-LD with `availability: InStock` hardcoded, `sku: AKULA-<id>` (not the real SKU), `offers.url = window.location.href` (can be the ObjectId URL or include query strings) and the base price only. The weight options (500 g / 1 kg / 2 kg at different prices) are ignored.
   - `SEO.jsx` contains a second Product builder with a made-up `priceValidUntil` (now + 30 days), an incomplete `shippingDetails` (no rate, which Google reports as invalid) and `aggregateRating.reviewCount` defaulting to `1` when unknown.
8. **Invented and contradictory business data in JSON-LD.** `LocalBusiness` hardcodes geo coordinates (15.5057, 80.0499, which is in Andhra Pradesh), defaults `addressRegion` to "Andhra Pradesh" and `openingHours` to `Mo-Sa 10:00-18:00`, and sets `priceRange: ₹₹`. The store's admin-entered contact settings (`GET /api/v1/settings/public`) give a **Noida, Uttar Pradesh** address, so the hardcoded geo contradicts the business's own data. There is also an invalid `ItemList` of `SiteNavigationElement`, and a `SearchAction` pointing at `/collections?search=` (Google retired the sitelinks search box in 2024).
9. **The 404 page is indexable.** `NotFound` passes `robots="noindex, follow"`, but `SEO` has no `robots` prop, so it renders `index, follow`. The server also returns `200` for unknown URLs, so they are soft 404s.
10. **No category landing pages.** Category navigation goes to `/collections?category=<Name>` (query-string variants of one page, with no unique metadata). `/collection/:id` exists, but its description is borrowed from the first product, it has no canonical logic, and nothing links to it.
11. **Generic titles and descriptions.** Shop: `Shop | Akula's Kitchen`. Home: falls back to "Authentic Flavors & Premium Culinary Experiences", which does not say what is sold. Some products have stored `seoDescription` values ending in a broken `"...."` (copied, truncated description text).
12. **robots.txt does not match intent.** It blocks `/cart/`, `/checkout/`, `/dashboard/` and others with trailing slashes, but the real routes are `/cart` and `/checkout`, so the rule never matches. Blocking also stops Google from seeing a `noindex`. There is no `X-Robots-Tag` header on private routes.

### Medium

13. **Admin cannot manage product SEO.** There are no fields for focus keyword, slug override, alt text, indexing or OG data. The slug cannot be edited and has no duplicate check (a duplicate title hits the unique index and fails with a raw error). Changing a title on edit keeps the old slug, which is good for stability but not visible to the admin.
14. **Images.** Gallery and product-card `alt` text is just the product title, identical for every image. Product image URLs are opaque Cloudinary IDs (renaming is not practical without breaking existing references, so URLs are kept).
15. **The breadcrumb's category link is a query URL** (`/collections?category=`). There is no BreadcrumbList on product pages.
16. **Store data visible on the product page vs. schema.** The storefront hardcodes `isOutOfStock = false` (`ProductCard.jsx`), while checkout rejects orders when `stock - reservedStock <= 0`. Structured data should use the real inventory state, which checkout enforces.
17. **Public product API leaks internal fields** (`qrCode`, `productUuid`, `warehouseLocations`) in listing responses. Not an SEO issue. Noted for the owners only and left unchanged (out of scope).

## 3. What already works

- Products have unique, lowercase, hyphenated slugs, and `GET /api/v1/products/:idOrSlug` resolves both forms.
- Soft delete plus `isActive` give a reliable "published" signal.
- Images are on Cloudinary, so OG-sized derivatives (`w_1200,h_630,c_fill`) can be produced by URL.
- `react-helmet-async` is already installed. No new head-management library is needed.
- The backend has `mongodb-memory-server`, so product SEO can be tested end to end against the real service layer.

## 4. Implementation plan

1. **One site URL.** Backend `SITE_URL` (`backend/src/config/seoConfig.ts`) and frontend `VITE_SITE_URL`, default `https://akulas.kitchen`, used for every canonical, sitemap and feed URL. Document the Vercel domain change required (make the apex primary, or set both env vars to the `www` origin).
2. **Product SEO model and generator** (backend, single source of truth): new fields on `Product`, a pure generator for slug, title, description, keywords, alt text, OG and canonical, override tracking (`seoOverrides`) so admin edits survive ordinary updates while generated values follow product changes, a slug-uniqueness check including retired slugs (`previousSlugs`), and Product/ProductGroup + Offer JSON-LD built from real price, variant and inventory data.
3. **Server-side head injection** without a framework migration: a Vercel serverless function (`frontend/api/seo-render.js`) handles indexable HTML routes. It fetches the built `index.html` and a resolved page descriptor from a new backend endpoint (`GET /api/v1/seo/page?path=`), and injects the title, meta, canonical, OG/Twitter, JSON-LD and a crawlable content shell (H1, description, product links). It returns `301` for ObjectId and retired-slug product URLs and a real `404` for unknown products. Every user agent gets the same HTML (no cloaking), and React replaces the shell on mount.
4. **Dynamic sitemap, merchant feed and robots**: backend endpoints proxied by Vercel rewrites. Delete the static `sitemap.xml` and the broken function. Rewrite `robots.txt`. Add `X-Robots-Tag: noindex` for private routes and the API.
5. **Frontend**: rewrite `SEO.jsx` (no invented data, `robots` prop, no duplicate JSON-LD, homepage-only Organization/WebSite schemas). Remove static head tags on boot. Use slug URLs in all product links. Add a new `/category/:slug` landing page with intro copy, breadcrumbs and an ItemList. Write unique copy for home, shop, menu and contact.
6. **Admin SEO panel** in the existing wizard: inputs with counters and validation, auto-generate and reset, duplicate-slug check, missing-field warnings, OG image preview, Google snippet preview.
7. **Tests and validation**: backend unit and integration tests (create, auto SEO, manual edit, price, stock, publish/unpublish, delete, images, sitemap, page metadata), plus a validation script run against the real live catalog.
